## Key algorithms & data flow

**Connection pragmas** (order is load-bearing): `busy_timeout = 5000` **first** (#238), then `foreign_keys = ON`, `journal_mode = WAL`, `synchronous = NORMAL`, `cache_size = -64000` (64 MB), `temp_store = MEMORY`, `mmap_size = 268435456` (256 MB). SQLite silently keeps prior journal mode if WAL is unsupported; `getJournalMode()` surfaces the effective one.

**Locking**: no SQLite-level app lock; a **`codegraph.lock`** file beside the DB (`FileLock`): exclusive-create (`wx`) containing the PID; stale if age ≥ **2 min** or PID dead; `codegraph unlock` just unlinks it. Cross-process write contention rides `busy_timeout=5000`.

**Node identity**: `id = "<kind>:" + hex(sha256("<filePath>:<kind>:<name>:<line>"))[0..32]`. Any line shift changes IDs — this drives the re-index edge-preservation protocol.

**Single-file re-index** (`storeExtractionResult`, chunk = 2000 rows per sub-transaction with an event-loop yield between): (1) skip if `content_hash` unchanged; (2) snapshot cross-file **incoming** edges (`getCrossFileIncomingEdgesWithTarget`: all kinds except `contains`, source in a different file) with target `(name, kind)`; (3) `deleteFile(path)` — deletes nodes by file (edges + unresolved_refs cascade via FK); (4) insert valid nodes (required fields: id, kind, name, filePath, language); (5) insert edges whose both endpoints are among inserted nodes; (6) re-insert snapshotted incoming edges re-resolved to new target IDs by `(kind + "\0" + name)`; unmatched ones are resurrected as unresolved refs from `metadata.refName/refKind` if stamped, else dropped (#899/#1240); (7) insert unresolved refs (denormalized filePath/language); (8) `upsertFile` **last** (crash ⇒ no file row ⇒ re-index).

**Full re-index discard**: never row-delete — `removeDatabaseFiles` unlinks `codegraph.db` (must succeed) then best-effort `-wal`/`-shm`. Long-lived holders heal via `isReplacedOnDisk`/`reopenIfReplaced` (compare `dev:ino` captured at open; Windows always returns null ⇒ never fires).

**WAL deferral** (#1231): bulk index sets `wal_autocheckpoint = 0` and starts the valve. Valve polls WAL file size every **2000 ms**; growth measured against `sizeAtLastFullBackfill` (WAL size never shrinks — a full backfill, `busy===0 && log===checkpointed`, resets the baseline). Soft threshold **256 MB** → fire one off-thread `PRAGMA wal_checkpoint(PASSIVE)`; hard cap **2×soft** → `backpressure()` parks the writer, loops passive passes (max **20**) until a full backfill. `foldNow()` = phase-boundary full fold.

**BFS** (`traverseBFS`): defaults `maxDepth=Infinity, edgeKinds=[], nodeKinds=[], direction='outgoing', limit=1000, includeStart=true`. Separate `visited` (set on dequeue) and `enqueued` (set on enqueue) sets (#1090); edge dedup key `source|target|kind|line??-1|col??-1`; adjacency sorted contains(0) < calls(1) < other(2); neighbors batch-fetched; node cap enforced per-add (#1087); **every** distinct edge among kept nodes is recorded (parallel edges preserved). DFS: recursive, same batch-fetch, per-add cap (#1088), records only tree edges.

**Callers/Callees**: follow incoming/outgoing edges of kinds `['calls','references','imports','instantiates']` (#774); mark `visited` **before** the depth check (#1086); depth counts from 0, `maxDepth=1` = direct only. `getCallGraph(depth=2)` = union of both plus focal.

**Impact radius** (`getImpactRadius`, default `maxDepth=3`): visited-before-depth-check (#1089). For container kinds `{class,interface,struct,trait,protocol,module,enum}`, first descend `contains` children **at the same depth**. Then follow all incoming edges **except `contains`** (#536), recording every dependency edge unconditionally, recursing depth+1 into unvisited sources.

**Path finding** (`findPath`): plain BFS over **outgoing** edges only (optionally kind-filtered), each queue entry carries its full path; returns first (shortest) path as `[{node, edge|null}, ...]` (first edge is null) or `null`. No depth cap.

**Type hierarchy**: ancestors via outgoing `['extends','implements']`, descendants via incoming, one shared `visited` set. `getAncestors` (containment): follows first incoming `contains` edge repeatedly with a cycle set.

**File dependency projection** (basis for `affected`): `getDependentFilePaths` — `SELECT DISTINCT src.file_path FROM edges e JOIN nodes tgt ON tgt.id=e.target JOIN nodes src ON src.id=e.source WHERE tgt.file_path=? AND e.kind != 'contains' AND src.file_path != ?`. Note `imports` edges are always same-file (file → its own import decls), so imports-only would return zero; the resolved symbol graph is the signal.

**searchNodes pipeline**: (1) `parseQuery` extracts `kind:`/`lang:|language:`/`path:`/`name:` (case-insens keys; quoted values unquoted; unknown prefixes/invalid values pass through to text); (2) if text: **FTS5** — query built by `::`→space (#173), strip `['"*():^]`, split whitespace, drop `AND|OR|NOT|NEAR` (case-insens), each term → `"term"*`, join `' OR '`; SQL: `SELECT nodes.*, bm25(nodes_fts, 0, 20, 5, 1, 2) as score FROM nodes_fts JOIN nodes ON nodes_fts.id = nodes.id WHERE nodes_fts MATCH ? [AND kind IN…][AND language IN…] ORDER BY score LIMIT max(limit*5,100) OFFSET ?`; score = `abs(bm25)`; FTS errors → empty. If filters-only (no text): match-all ordered by name, limit×5. (3) empty & len≥2 → **LIKE** search: score CASE exact=1.0 / starts-with=0.9 / contains=0.8 / qualified contains=0.7 / else 0.5, WHERE name LIKE %q% OR qualified_name LIKE %q% OR name LIKE q%, `ORDER BY score DESC, length(name) ASC`. (4) still empty & len≥3 → **fuzzy**: `maxDist = len≤4 ? 1 : 2` over all distinct names via `boundedEditDistance` (bounded Levenshtein, early-exit maxDist+1, case-folded by caller); candidates sorted by dist, capped at `max(limit*2, 50)`; per name `SELECT … WHERE name=? LIMIT 5`; score `1/(1+dist)`. (5) **exact-name supplement**: for each whitespace term len≥2, `name = ? COLLATE NOCASE LIMIT 20`, added at max existing FTS score. (6) **rescore**: `score += kindBonus + scorePathRelevance + nameMatchBonus`, sort desc, trim to limit. (7) hard `path:`/`name:` substring filters applied last (case-insens).

Scoring constants — `kindBonus`: function/method 10, interface/trait/protocol/route 9, class/component 8, type_alias/struct 6, enum 5, module/namespace 4, property/field/constant/enum_member 3, variable 2, import/export 1, parameter/file 0. `nameMatchBonus`: exact (whitespace-stripped, lowered) = 80; multi-token query exactly matching name = 60; prefix = `round(10 + 30 * len(query)/len(name))`; all camel-split terms contained = 15; substring = 10; else 0. `scorePathRelevance`: per original query word (project-name tokens dropped, #720): filename contains sub-token +10, dir +5, else path +3; test files −15 unless query contains "test"/"spec". `findNodesByExactName`: two-pass; "distinctive" names are those matching < 10 files; co-location boost +20; perNameLimit `max(8, ceil(limit/names))`, fetch `max(perNameLimit*3, 50)`.

**Segment vocab**: `splitIdentifierSegments` — Unicode letter/digit runs split at `(?<=[\p{Ll}\p{N}])(?=\p{Lu})` and `(?<=\p{Lu})(?=\p{Lu}\p{Ll})`; lowered; bounds MIN 2 / MAX 32 chars, MAX 12 segments/name, digit-only dropped. Written on `insertNode`/`updateNode` for kinds ≠ `file`/`import`, guarded by an in-memory 65 536-entry name set + `INSERT OR IGNORE`. Deletes leave orphan rows on purpose (rows are proposals, re-verified against `nodes`); full index calls `clearNameSegmentVocab()` first. Prose lookup constants: MAX 16 candidates, 4–24 chars, diacritics stripped (NFD, drop `\p{M}`), English stopword list; plural folding per `segmentLookupVariants` (`(x|sh|ss|zz)es`→strip2; `(ch|s|z|o)es`→strip2 AND strip1; bare `-s` not `-ss`→strip1).

**Dominant/route files**: `getDominantFile` — top 20 files by same-file edge count (`JOIN nodes n ON e.source=n.id JOIN nodes m ON e.target=m.id WHERE n.file_path=m.file_path`), filter test/generated (`isLowValueFile` regex set + `isGeneratedFile`), null if top < **20** edges. `getTopRouteFile` — top 20 by `kind='route'` count; null if total < 3, top < 3, or top/total < **0.30**. `getRoutingManifest(limit=40)` — route→handler join over edge kinds `('references','calls')` into handler kinds `('function','method','class')`, null if < 3 rows after filtering.

`SQLITE_PARAM_CHUNK_SIZE = 500` for every IN-list (getNodesByIds, getExistingNodeIds, unresolved-by-files, delete/retry paths). Node LRU cache: 1000 entries, invalidated on insert/update/delete/deleteByFile.

## Wire/contract surfaces

**Schema (must match byte-for-byte semantics)** — tables `schema_versions(version PK, applied_at, description)`, `nodes(id TEXT PK, kind, name, qualified_name, file_path, language, start_line, end_line, start_column, end_column, docstring, signature, visibility, is_exported INT DEF 0, is_async, is_static, is_abstract, decorators JSON, type_parameters JSON, return_type, updated_at)`, `edges(id INTEGER PK AUTOINCREMENT, source→nodes ON DELETE CASCADE, target→nodes ON DELETE CASCADE, kind, metadata JSON, line, col, provenance DEF NULL)`, `files(path PK, content_hash, language, size, modified_at, indexed_at, node_count DEF 0, errors JSON)`, `unresolved_refs(id PK, from_node_id→nodes CASCADE, reference_name, reference_kind, line, col, candidates JSON, file_path DEF '', language DEF 'unknown', status DEF 'pending', name_tail DEF '')`, `name_segment_vocab(segment, name, PK(segment,name)) WITHOUT ROWID`, `project_metadata(key PK, value, updated_at)`. Indexes: nodes on kind, name, qualified_name, file_path, language, (file_path,start_line), `lower(name)`; edges on kind, (source,kind), (target,kind), provenance, **UNIQUE** `(source, target, kind, IFNULL(line,-1), IFNULL(col,-1))` (#1034 — makes `INSERT OR IGNORE` a real dedup; narrow source/target indexes deliberately absent); files on language, modified_at; unresolved on from_node_id, reference_name, file_path, (from_node_id,reference_name), status, partial `name_tail WHERE status='failed'`. FTS: `CREATE VIRTUAL TABLE nodes_fts USING fts5(id, name, qualified_name, docstring, signature, content='nodes', content_rowid='rowid')` with AFTER INSERT/DELETE/UPDATE triggers (`nodes_ai/nodes_ad/nodes_au`) using the external-content delete protocol. Timestamps are ms epoch (`strftime('%s','now')*1000` / `Date.now()`).

**Migrations** (v1 = schema.sql): v2 project_metadata + unresolved file_path/language + edges.provenance; v3 `lower(name)` index; v4 drop `idx_edges_source`/`idx_edges_target`; v5 `nodes.return_type`; v6 edge dedup (`DELETE … WHERE id NOT IN (SELECT MIN(id) … GROUP BY source,target,kind,IFNULL(line,-1),IFNULL(col,-1))`) + unique index; v7 name_segment_vocab; v8 unresolved status/name_tail columns (PRAGMA table_info-guarded) + indexes. Each runs in its own transaction and appends to `schema_versions`.

**Enums as stored strings**: NodeKind (22) and EdgeKind (12) exactly as in SeleneCode's `selene-core`. `provenance` ∈ `'tree-sitter' | 'scip' | 'heuristic'` (NULL allowed). `unresolved_refs.status` ∈ `'pending' | 'failed'`. `reference_kind` may also be `'function_ref'` (internal, never an edge kind). Booleans stored 0/1; `decorators`/`type_parameters`/`candidates`/`errors` are JSON arrays; `edges.metadata` a JSON object (synthesized edges carry `metadata.synthesizedBy` + `registeredAt`; edge re-resurrection reads `metadata.refName`/`refKind`).

**Error semantics**: `DatabaseConnection.open` throws `Database not found: <path>`; `getContext` throws `Node not found: <id>`; `FileLock.acquire` throws `CodeGraph database is locked by another process (PID <pid>). If this is stale, run 'codegraph unlock' or delete <path>`. Traversals **never throw** on unknown IDs — they return the empty `Subgraph {nodes:Map, edges:[], roots:[]}` or `null` (findPath). `searchNodes` swallows FTS syntax errors (empty result). `runMaintenance`/`checkpointWalPassive` are best-effort/never-throw. `SearchResult.score` is explicitly relative-only, not normalized (BM25 magnitude vs ~0–1 LIKE/fuzzy scores).

**Env vars**: `CODEGRAPH_WAL_VALVE_MB` (soft valve threshold; non-numeric/≤0 → 256).

**Files on disk**: `.codegraph/codegraph.db` (+ `-wal`, `-shm`), `.codegraph/codegraph.lock` (PID text).

## Rust port notes

- **GraphStore trait shape**: everything the rest of the codebase does through the DB is enumerated in `QueryBuilder` above — that list *is* the candidate trait. The traversals themselves live entirely in code and need only: point node get, batched node get, incoming/outgoing edges filtered by kind (+provenance for outgoing), and the two file-projection queries. The FTS pipeline, dominant-file/route aggregates, and segment-vocab queries are SQL-shaped; decide per PRD §5.4 whether they become SurrealQL or portable primitives (the IndraDB/redb+Tantivy fallback can't run arbitrary SQL — the ranked-search pipeline (steps 2–7) is pure code over a candidate fetch, so keep only "candidate fetch by prefix/substring/exact/fuzzy-name-list" in the trait and do scoring in `selene-graph`/`selene-context`).
- Placement: `selene-db` — connection, schema/migrations, all CRUD/statement equivalents, WAL valve (SQLite-specific; likely drop for SurrealDB but the deferral *concept*—bulk-write mode + bounded background compaction—may map to backend-specific tuning). `selene-graph` — GraphTraverser + GraphQueryManager. `selene-context`/`selene-mcp` — search scoring + parser (`query-parser`, `query-utils`, `identifier-segments` are DB-independent pure functions; ideal first ports with their test suites).
- **Recursion → iteration**: `dfsRecursive`, `getCallersRecursive`, `getImpactRecursive`, `findCircularDependencies` are stack-recursive; deep graphs can overflow — reimplement with explicit stacks in Rust.
- **JS quirks to not copy**: `getNodesByNamePrefix` upper bound is `prefix + '\u{FFFF}'` — use proper key-successor logic. `Map` iteration order (insertion) is relied on for LRU and for `Subgraph.nodes` ordering — use `indexmap`/`lru`. `Infinity` default `maxDepth` needs `Option<u32>` or `u32::MAX`. bm25() returns negative; code stores `abs()`.
- **Semantic subtleties**: `INSERT OR REPLACE` on nodes fires the FTS delete+insert triggers via rowid — an embedded-DB port must keep search-index consistency on node overwrite. Edge identity = (source, target, kind, line-or-−1, col-or-−1) — must be a uniqueness constraint at the storage layer, not app-side dedup. Impact recursion into `contains` children happens at the **same** depth. Callers/callees edge-kind whitelist `calls|references|imports|instantiates` is a behavior contract.
- **Suspected dead/buggy TS**: `SearchOptions.includePatterns/excludePatterns/caseSensitive` are declared but never honored anywhere in `queries.ts`. `getIncomingEdges` has no provenance param (asymmetric with outgoing). `findByQualifiedName` is an acknowledged full-scan ("inefficient for large graphs"). `getStemVariants` mints non-words by design (prefix-match only). `findCircularDependencies` reports each cycle once per entry path, may duplicate rotated cycles. `deleteEdgesBySource` appears unused by this subsystem's callers (kept for API). `Subgraph.confidence` is set only by the context/search layer, never by these traversals.
- **Do not drift**: pragma values and order, chunk size 500, cache size 1000, valve constants (256 MB / 2× / 20 passes / 2000 ms), BM25 weights `(0, 20, 5, 1, 2)`, fetch multiplier 5× (min 100), fuzzy dist 1/2 at len ≤4/>4, follow-up cap `max(limit*2,50)`, all scoring bonuses, dominant-file min 20 edges, route thresholds 3/3/30 %, retry ceiling 500, lock staleness 2 min, busy_timeout 5000, segment bounds 2/32/12, prose bounds 4/24/16, `MAX_SEGMENTED_NAMES` 65536, `STORE_CHUNK` 2000, node-ID hash truncation 32 hex chars with `kind:` prefix.
